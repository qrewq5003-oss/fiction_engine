# MEMORY GRAPH

**Модуль:** 06_STATE_ENGINE/memory_graph.md  
**Назначение:** Отслеживание знаний персонажей и информационных потоков

---

## 🎯 НАЗНАЧЕНИЕ

Memory Graph отслеживает:
- **Кто что знает** (и с какой главы)
- **Кто от кого узнал** (цепочки информации)
- **Кто что скрывает** (секреты)
- **Ложные убеждения** (персонаж думает X, но на самом деле Y)
- **Информационные разрывы** (A знает, B не знает — драма!)

**Для чего:** Избежать ошибок типа "персонаж забыл, что знал" или "персонаж знает то, что не мог узнать".

---

## 📊 СТРУКТУРА ГРАФА

### Узлы (Nodes):

**1. ПЕРСОНАЖИ** — кто знает
**2. ИНФОРМАЦИЯ** — что знают
**3. СОБЫТИЯ** — когда узнали

### Рёбра (Edges):

**KNOWS** — связь "персонаж знает информацию"  
**TOLD_BY** — связь "персонаж узнал от другого персонажа"  
**DISCOVERED** — связь "персонаж узнал из события"

```
ИНФОРМАЦИЯ: "Петров — убийца"

[Ковалёв] --KNOWS(с гл.125)--> [Инфо: "Петров=убийца"]
    ↑                                   ↑
    |                                   |
DISCOVERED(гл.125)              TOLD_BY(гл.127)

СКРЫВАЕТ:

```

## 📋 ФОРМАТ ЗАПИСИ ЗНАНИЯ

### Полная запись знания персонажа:

```yaml
character: "char_001" # Ковалёв
knowledge_id: "know_045"

information:
  type: "fact"  # fact, suspicion, belief, secret
  content: "Петров — убийца партнёра"
  confidence: 95  # 0-100 (насколько уверен)
  accuracy: 100   # 0-100 (насколько верно на самом деле)

acquisition:
  chapter: 125
  method: "discovered"  # discovered, told, deduced, overheard
  source:
    type: "evidence"
    description: "Нашёл отпечатки Петрова на месте преступления"
  witnesses: []  # кто ещё присутствовал при открытии

sharing:
  told_to:
    - character: "char_002" (Анна)
      chapter: 127
      context: "Доверяет ей"
    - character: "char_015" (Начальник)
      chapter: 130
      context: "Официальный доклад"
  
  hiding_from:
    - character: "char_007" (Коллега-предатель)
      reason: "Не доверяет"
      until_chapter: null  # скрывает до конца

impact_on_actions:
  - chapter: 126
    action: "Начал слежку за Петровым"
  - chapter: 128
    action: "Противостояние с Петровым"

emotional_impact:
  initial: "шок, гнев"
  long_term: "решимость отомстить"

related_knowledge:
  - know_012: "Партнёр был убит" (база)
  - know_038: "Петров работал с партнёром" (контекст)
```

## 🔗 ИНФОРМАЦИОННЫЕ ЦЕПОЧКИ

### Типы передачи информации:

**1. ПРЯМАЯ (Direct)**
```
A говорит B напрямую
Глава 127: Ковалёв рассказывает Анне о Петрове
```

**2. НЕПРЯМАЯ (Indirect)**
```
A говорит B, B говорит C
Глава 127: Ковалёв → Анна
Глава 128: Анна → Начальник
Результат: Начальник узнал через Анну
```

**3. ПОДСЛУШИВАНИЕ (Overhear)**
```
A говорит B, C слышит случайно
Глава 130: Ковалёв говорит Анне, коллега подслушивает
```

**4. ОБНАРУЖЕНИЕ (Discovery)**
```
A находит информацию самостоятельно
Глава 125: Ковалёв находит улику
```

**5. ДЕДУКЦИЯ (Deduction)**
```
A делает вывод из известного
Глава 135: Анна понимает, что Петров — наёмник (из улик)
```

---

### Пример цепочки:

```yaml
information_chain:
  info: "Петров — наёмник, а не одиночка"
  
  origin:
    chapter: 125
    source: "Улика (записка заказчику)"
    discovered_by: "char_001" (Ковалёв)
  
  spread:
    - step: 1
      chapter: 127
      from: "char_001"
      to: "char_002" (Анна)
      method: "told"
      context: "Доверяет ей, обсуждают дело"
    
    - step: 2
      chapter: 128
      from: "char_002"
      to: "char_015" (Начальник)
      method: "told"
      context: "Официальный доклад"
    
    - step: 3
      chapter: 130
      from: "char_015"
      to: "char_020" (Другой отдел)
      method: "told"
      context: "Координация"
  
  who_doesnt_know:
    - "char_045" (Петров) — не знает, что раскрыт
    - "char_007" (Коллега-предатель) — Ковалёв скрывает
  
  dramatic_irony:
    chapter: 132
    description: "Петров думает, что не раскрыт, а полиция уже ведёт слежку"
```

## 🎭 ТИПЫ ЗНАНИЙ

### 1. ФАКТЫ (Facts)
```yaml
type: "fact"
content: "Петров был на месте преступления"
accuracy: 100
verifiable: true
```

### 2. ПОДОЗРЕНИЯ (Suspicions)
```yaml
type: "suspicion"
content: "Петров может быть убийцей"
accuracy: 80  # может быть неверно
confidence: 60  # персонаж не уверен
```

### 3. УБЕЖДЕНИЯ (Beliefs)
```yaml
type: "belief"
content: "Начальник честный человек"
accuracy: 0   # на самом деле коррумпирован
confidence: 95  # но персонаж уверен
```

### 4. СЕКРЕТЫ (Secrets)
```yaml
type: "secret"
content: "Ковалёв работал под прикрытием 5 лет назад"
accuracy: 100
known_by: ["char_001", "char_015"]
hidden_from: ["char_002", "char_007", ...]
reveal_planned: 180  # глава раскрытия
```

### 5. ЛОЖНАЯ ИНФОРМАЦИЯ (Misinformation)
```yaml
type: "misinformation"
content: "Свидетель видел Иванова на месте"
accuracy: 0  # Иванов не был там
confidence: 70  # но персонаж верит
planted_by: "char_045" (Петров обманул)
```

## 🔍 ПРОВЕРКИ ЛОГИКИ

### Автоматические проверки:

**1. Невозможное знание:**
```
Глава 125: Ковалёв находит улику
Глава 124: Анна упоминает улику в разговоре
⚠️ ОШИБКА: Анна не могла знать раньше Ковалёва
```

**2. Забытое знание:**
```
Глава 125: Ковалёв узнаёт имя убийцы
Глава 135: Ковалёв спрашивает "Кто убийца?"
⚠️ ОШИБКА: Персонаж забыл, что знал
```

**3. Информационный разрыв без объяснения:**
```
Глава 125: Только Ковалёв знает
Глава 126: Начальник обсуждает это
⚠️ ОШИБКА: Как начальник узнал? Нужна сцена передачи
```

**4. Мёртвый информатор:**
```
Глава 120: Свидетель убит
Глава 130: Персонаж узнаёт от свидетеля
⚠️ КРИТИЧЕСКАЯ ОШИБКА
```

## 🎯 КОМАНДЫ

### Основные команды:

```
"Что [персонаж] знает на главу N?"
→ Список всех знаний с уровнем уверенности

"Как [персонаж] узнал [информацию]?"
→ Цепочка: источник → метод → глава

"Кто знает [информацию] на главу N?"
→ Список персонажей

"Проверить логику знаний в главе N"
→ Поиск ошибок (невозможное знание, забытое)

"Создать драматическую иронию: [ситуация]"
→ План: кто что знает/не знает

"Показать информационные разрывы"
→ Кто что должен знать, но не знает
```

## 🎨 ДРАМАТИЧЕСКАЯ ИРОНИЯ

### Три уровня знания:

```
УРОВЕНЬ 1: Персонаж A знает
УРОВЕНЬ 2: Персонаж B не знает
УРОВЕНЬ 3: Читатель знает обоих

Результат: НАПРЯЖЕНИЕ
```

**Примеры:**

**Тип 1: Читатель знает больше персонажа**
```
Глава 110:
- Читатель видит: Коллега — предатель
- Ковалёв НЕ знает: доверяет коллеге
Напряжение: "Не доверяй ему!"
```

**Тип 2: Персонаж знает больше читателя**
```
Глава 95:
- Ковалёв знает: Тайна из прошлого
- Читатель НЕ знает: что именно
Напряжение: "Что он скрывает?"
```

**Тип 3: Два персонажа не знают друг о друге**
```
Глава 140:
- Ковалёв идёт арестовать Петрова
- Петров планирует убить Ковалёва
- Читатель знает: оба плана
Напряжение: "Кто кого опередит?"
```

## 🔥 КРИТИЧЕСКИЕ ПРАВИЛА

1. **Отслеживай каждое знание**
   - Кто узнал? Как? Когда?
   - Цепочка должна быть логичной

2. **Проверяй перед написанием**
   - Может ли персонаж это знать?
   - Откуда он узнал?

3. **Используй драматическую иронию**
   - Разрывы в знаниях = драма
   - Планируй, кто что знает/не знает

4. **Не забывай знания**
   - Если персонаж узнал — он помнит
   - Исключение: травма, амнезия (отметь!)

5. **Логичные цепочки**
   - Информация не телепортируется
   - Нужна сцена передачи (или подслушивание)

## 📝 ИТОГ

Memory Graph = **информационная структура истории**.

Для серий 100+ глав с 10+ персонажами это **критично**.

Без него — персонажи магически узнают информацию или забывают очевидное.
С ним — логичные знания, драматическая ирония, tight plotting.
