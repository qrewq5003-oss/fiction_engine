# 🌍 WORLD STATE KERNEL ENGINE

**Назначение:** Единое динамическое состояние мира с отслеживанием причинно-следственных связей, противоречий и переноса между книгами серии.

**Статус:** ADVANCED ENGINE (уровень 5++/5)

---

## 📋 БАЗОВАЯ КОНЦЕПЦИЯ

### Проблема без World State Kernel:
- Персонаж в двух местах одновременно (забыли про timeline)
- Политическое событие произошло, но мир не изменился
- Экономический кризис упомянут, но никто не беднеет
- В серии книг: противоречия между томами
- Культурные изменения не влияют на персонажей

### Решение с World State Kernel:
- ✅ **Снимок мира на любой момент времени**
- ✅ **События автоматически меняют состояние**
- ✅ **Детекция противоречий (validation)**
- ✅ **Риски и угрозы отслеживаются**
- ✅ **Перенос состояния между книгами серии**

## ПРАКТИКА (для написания — читай это)

**Три вопроса перед каждой главой:**
1. Это событие возможно в текущем состоянии мира? (локации, политика, физика)
2. Какие последствия второго порядка? (не только прямые — ripple effects)
3. Что мир "запомнит" после этой главы? (обнови состояние)

**Три ошибки которые убивают доверие читателя:**
❌ Персонаж в двух местах одновременно — не отслеживали локации
❌ Война началась без признаков — tensions не нарастали в предыдущих главах
❌ Экономика не реагирует — персонаж нашёл золото, цены не изменились

**Правило нарастания:** крупные события не происходят внезапно.
Война: tensions 45% → 62% (инцидент) → 78% (провал переговоров) → 91% (ультиматум) → война.
Без нарастания — читатель не верит.

**Правило ripple:** каждое событие меняет мир на 2-3 уровня глубины.
Кража кристалла → Академия начинает розыск → Дефицит магии → Рост цен → Паника.
Достаточно упомянуть один уровень вглубь — мир ощущается живым.

**❌ DON'T:**
- Не игнорируй противоречия ("потом исправлю") — они накапливаются
- Не делай события "из воздуха" — всё должно иметь причину в состоянии мира
- Не нарушай законы мира без явного объяснения внутри текста

### ПРОЦЕСС 1: Планирование события

**ПЕРЕД написанием сцены:**

1. Проверь текущее состояние мира (world_state.json)
2. Спроси: "Это событие возможно в текущем состоянии?"
3. Спроси: "Какие будут последствия?"
4. Запиши событие в causality_tracker.json
5. Обнови world_state.json

**Пример:**
```
ПЛАН: Персонаж украдёт магический кристалл из хранилища

ПРОВЕРКА world_state.json:
- magic_system.magic_depletion.current_level = 78%
- Кристаллы под охраной Академии
- Кража будет замечена → Последствия

ПОСЛЕДСТВИЯ (добавляем в causality_tracker):
- Прямые: Академия начнёт розыск
- Ripple: Дефицит магии → Рост цен
- Butterfly: Если не найдут → Паника → Реформы системы

ОБНОВЛЕНИЕ world_state:
- magic_depletion.current_level: 78% → 76%
- political.active_investigations += "Кража кристалла"
```

### ПРОЦЕСС 2: Валидация противоречий

**ПОСЛЕ написания главы:**

1. Прогони через truth_table.json
2. Проверь временные метки
3. Проверь перемещения персонажей
4. Проверь физическую возможность событий

**Автоматическая проверка:**
```python
def validate_scene(scene_data, world_state):
    errors = []
    
    # Проверка 1: Персонаж в одном месте
    for character in scene_data.characters:
        other_scenes = get_scenes_at_same_time(scene_data.timestamp)
        if character in other_scenes:
            errors.append(f"{character} в двух местах одновременно")
    
    # Проверка 2: Физически возможное время
    if scene_data.travel:
        real_time = calculate_travel_time(
            scene_data.travel.from,
            scene_data.travel.to,
            scene_data.travel.method
        )
        if scene_data.travel.time < real_time:
            errors.append(f"Путешествие слишком быстрое: {scene_data.travel.time} < {real_time}")
    
    # Проверка 3: Состояние мира корректно
    required_state = scene_data.requires_world_state
    actual_state = world_state.get_state_at(scene_data.timestamp)
    if not matches(required_state, actual_state):
        errors.append(f"Несоответствие состояния мира")
    
    return errors
```

## 🚀 ПРИМЕР ПОЛНОГО ЦИКЛА

### Сценарий: "Покушение на императора"

#### ШАГ 1: ПЛАНИРОВАНИЕ

```
ВОПРОСЫ перед написанием:

1. КТО организовал? (Проверяем political.factions)
   → Республиканское подполье (influence 23%, мотив есть)

2. КОГДА возможно? (Проверяем timeline)
   → Во время коронации (много народу, охрана растянута)

3. КАК технически? (Проверяем world_state)
   → Снайпер? (Нет огнестрела в мире)
   → Магия? (Есть, но детектируется Академией)
   → Яд? (Возможно, но нужен доступ к еде)
   → Решение: Отравленный клинок во время церемонии

4. ПОСЛЕДСТВИЯ если успех?
   → Наследник малолетний → Регентство → Борьба за власть

5. ПОСЛЕДСТВИЯ если провал?
   → Репрессии → Рост напряжения → Ускорение восстания
```

#### ШАГ 2: НАПИСАНИЕ с ВАЛИДАЦИЕЙ

```
СЦЕНА: Покушение

[Клод проверяет в real-time]
✅ Убийца может быть в толпе (есть в truth_table)
✅ Клинок пронесён (охрана проверяла магию, не оружие)
✅ Император без доспехов (церемониальная одежда)
⚠️ WARNING: Удар в сердце = мгновенная смерть
   → Но нужен эмоциональный прощальный монолог?
   → ИСПРАВЛЕНИЕ: Удар в лёгкое (медленная смерть, 5 минут на слова)
```

## 🎓 СОВЕТЫ ПО ИСПОЛЬЗОВАНИЮ

### ✅ DO:
- Планируй крупные события заранее (внеси в causality_tracker)
- Проверяй world_state перед каждой главой
- Обновляй состояние сразу после написания
- Используй validation после каждой главы
- Записывай даже мелкие изменения (они могут стать важными)

### ❌ DON'T:
- Не игнорируй противоречия ("потом исправлю")
- Не забывай про ripple effects (второй-третий порядок последствий)
- Не делай события "из воздуха" (всё должно иметь причину)
- Не нарушай установленные законы мира без объяснения
- Не забывай про время (events take time to unfold)

## 🔮 ADVANCED TIPS

### ТРОП: "Внезапная война"

**ПЛОХО:**
```
Глава 15: Мирные переговоры
Глава 16: ВНЕЗАПНО ВОЙНА началась
```

**ХОРОШО (с World State):**
```
Глава 10: political.tensions["Empire_vs_East"] = 45%
Глава 12: Инцидент на границе → tensions = 62%
Глава 14: Провал переговоров → tensions = 78%
Глава 15: Ультиматум → tensions = 91%
Глава 16: Война (предсказуемо по графику напряжения)
```

### ТРОП: "Удобная экономика"

**ПЛОХО:**
```
Персонаж беден → находит золото → богат → покупает армию
(экономика не реагирует)
```

**ХОРОШО (с World State):**
```
economy.gold_influx = +1000 слитков
→ economy.inflation_rate += 8%
→ economy.gold_value -= 15%
→ Персонаж богат, но золото обесценилось
→ Покупательная способность меньше ожидаемой
→ Сюжетные последствия: нужен другой план
```

## ## MINI (QUICK режим — суть за 10 строк)

**World State = снимок мира в любой момент времени.** Событие случилось — мир изменился. Всегда.

**Три типа противоречий которые убивают доверие:**
1. **Персонаж в двух местах:** не отслеживали timeline.
2. **Событие без последствий:** война началась, но все живут как прежде.
3. **Противоречие между томами:** в книге 1 замок разрушен, в книге 2 герой туда идёт.

**Что должен помнить мир после этой главы:**
Политика: [изменилось ли что-то в балансе сил?]
Персонажи: [кто узнал что? кто теперь знает о ком?]
Физический мир: [что уничтожено, создано, изменено?]
Информация: [какие секреты раскрыты / созданы?]

**Правило на главу:** после написания — обнови State Engine. Что изменилось в мире? Если ничего — глава не работает.
**Красный флаг:** персонаж не реагирует на событие которое должно было его задеть.
