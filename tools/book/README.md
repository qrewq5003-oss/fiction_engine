# Книга через приложение

Скрипты, которыми написана книга «Фон» (19.10.2026, 24 главы): Claude ведёт приложение так, как вёл бы автор, — через его маршруты, а не правкой базы.

| Скрипт | Что делает |
| --- | --- |
| `setup_book.py` | Заводит проект в FE (жанр, стиль, подготовка, голос) и в планировщике, связывает их. Пишет `setup.json`. |
| `run_book.py N M` | Пишет главы N..M: сцены в планировщик → экспорт плана → «Мастерская» → сверка с планом → «Принять» (лучший по судье круг) → проверки после главы. |
| `smoke.py` | Дымовая книга: 3 главы по `smoke/book.json` на копии FE :5300 и планировщика :5301 из этой рабочей копии, своя пустая база; после прогона — проверки движка, отчёт `smoke_report.txt`. |
| `voice_update.py A B [--apply]` | Обновляет голос: «Голос → Проверить» по главам, манера без модели, эталоны из книги выбирает модель другой семьи. |

Запуск — из папки книги (`book.json` там же): `cd моя_книга && python ../fiction_engine/tools/book/run_book.py 1 4`. FE на :5000, планировщик на :5001 (`BOOK_FE`, `BOOK_PL` — другие адреса), токен — `~/fiction_engine/api_token`.

## Дымовая книга (`smoke.py`)

Четыре ошибки «Фона» нашлись только на настоящей книге: удаление проекта, обрезка профиля голоса, рабочие заметки писателя в главе, дубль персонажа. Тесты их не ловили. Дымовая книга — тот же путь «как автор» на коротком фиксированном плане: план всей книги сразу на доске (`plan_ahead`), один круг правки, без проверки логики и голоса (`BOOK_SMOKE=1`).

Проверки после прогона: главы написаны и не короче половины объёма; нет рабочих заметок; нет дублей персонажей в State; маркер из «Заметок автора» не попал ни в одну запись, кроме самой подготовки; забеганий нет; план вперёд дошёл до сторожа приложения; принят лучший по судье круг; откат последней главы возвращает State; проект удаляется. Противоречия библии идут в отчёт. Если что-то сломано, код выхода 1.

Запуск: `python tools/book/smoke.py` питоном FE (`fiction_engine/.venv`). Прогон идёт в `.ab_work/smoke/<время>`. `--check DIR` повторяет проверки по готовому прогону без копии. Вызовы моделей идут по подпискам (около 3–4 % недели ChatGPT), поэтому запускать вручную, перед крупными изменениями движка и не во время другой книги: одна подписка — один процесс. Копия гасится в конце, на чужие процессы портов 5300/5301 скрипт не посягает: если порт занят, он остановится.

## `book.json`

- `name`, `genre`, `genre_key`, `style_key`, `roles` (необязательно; по умолчанию Sonnet пишет и правит, критик Haiku 5.5, судья Sol).
- `prep`: `characters`, `world`, `plot`, `notes` — разделы «Подготовки». `notes` писателю не уходит.
- `voice`: `name`, `profile` (до 1800 символов).
- `plan_ahead` (необязательно): план всей книги — на доску сразу, сцены главы берутся с доски по названию; планировщик шлёт сцены после главы сторожу забеганий приложения.
- `volume` (необязательно): строка объёма в задании главы.
- `chapters`: `task` («Глава N. … Глава заканчивается …») и `scenes` — у сцены `title`, `location`, `time`, `day`, `chars`, `what`, `emo`, `hold` (что в сцене не раскрывать и до какой главы).

## Проверки после главы (`run_book.py`)

- **Сторож забеганий** (модель другой семьи): случилось ли в главе то, что по плану будет позже. «Раскрытие» — стоп, «деталь» — в журнал. Знает прошлые главы.
- **Привычки** черновика и финала: «, как», «как человек, который», «словно / будто», присказки, повторы пар слов.
- **Логика выводов** героя: на что опирается каждый вывод расследования.
- **Голос** — «Голос → Проверить».
- Стоп: смена активного проекта в FE, рабочие заметки модели в главе, лимит подписки (окно ChatGPT ≥ 95 % — ждать, неделя ≥ 85 % — стоп).

## Уроки «Фона»

- В подготовку — только то, что известно с главы 1. Детали-улики (приметы, машины, связи) — в план главы, где их находят: писатель видит подготовку с первой главы и раскрывает рано.
- Присказки героям не задавать ни в карточке, ни в эталоне голоса — писатель их тиражирует (3–5 раз за главу).
- Правила в голосе модель цитирует («наблюдение — вывод» стало репликой героя). В профиле — манера по замеру и эталоны из книги.
- Натяжки логики правкой не лечатся: фильтр откатывает смягчённые фразы как более слабую прозу.
- Правка иногда ухудшает главу (черновик 32 → 29) — принимать лучший по судье круг, а не последний.
- Ложные следы закладывать в план сразу, со снятием в конкретной главе.
- Объём задавать по сценам («каждая сцена не меньше 900 слов»): общая строка давала 1900 слов вместо 2500.
