# Разбор ошибок Fiction Engine и планировщика, 20–22.10.2026

22.10.2026 · копия документа из Claude Docs: https://claude.ai/artifact/VZ2kAwHoa4XoPVJmmuM9Xq

За три дня пять заходов нашли около 180 ошибок в Fiction Engine и планировщике; около 155 исправлено и влито в master (PR #130, #132, #139–#160), почти всё — с тестами. Главное, что они закрывали: модели получали устаревшие или будущие данные книги, порча данных при обычной работе и сбои, которые выглядели как успех.

## Как искали

Каждый разбор шёл в два этапа: сначала поиск только чтением, потом исправление пакетами с тестами. Код и рабочие базы при поиске не менялись.

1. **Повод.** Конкретный сбой на настоящей книге: анализ главы по черновику (скрин автора), писатель «Ночной смены», не знавший плана, протечка памяти Claude Code в вызовы модели.
2. **Классы, а не случаи.** По поводу формулировался класс ошибок («производное считается по одной версии текста и не обновляется», «маршруты, которые пересекаются», «сбой выдаётся за успех») — и искались все его проявления.
3. **Параллельные проходы.** От трёх до шести агентов, каждый на свой класс или часть кода, только чтение; базы — копии «Фона», «Ночной смены», «Инженера», открытые read-only.
4. **Подтверждение.** Находка засчитывалась, только если подтверждена кодом, данными базы или проверочным скриптом на одноразовой базе. Неподтверждённое шло отдельным списком.
5. **Сверка с кодом.** Перед мелочами отдельный проход сверил ~80 находок с текущим master: что уже исправлено, что осталось.
6. **Исправление пакетами.** Группа находок → ветка → тесты на каждую → полный pytest, mypy, проверки CI (sigcheck, pitfalls, undefined, proofcheck, scoping, getcheck), снимок заданий моделей «Фона» гл.12 → PR → вливание по слову автора.
7. **Данные задним числом.** Код не чинит уже испорченные данные: разовые правки (заметки, история запусков, библия «Фона») — на копии, с показом разницы, потом на живой базе после копии.

## Самые серьёзные находки

Десять ошибок, которые сильнее всего влияли на книги или на данные автора.

1. **Память Claude Code уходила в каждый вызов Claude по подписке.** claude CLI запускался из папки репозитория и подхватывал память разработчика (MEMORY.md). Замеры с ролями Claude до #147 — с оговоркой.
2. **Переписывание ранней главы получало конец книги.** У «Фона» нет снимков State до глав, и писатель гл.12 видел бы «Марат обвинён» и разгадку в «ЗНАЕТ» героини.
3. **Анализ главы по черновику.** В «Ночной смене» правка убрала ошибку «мы с тобой вдвоём в палате», а критик гл.3 упрекал главу этим разрывом из анализа черновика.
4. **План побеждал текст в библии.** В блоке гл.25 «Фона» 26 из 40 строк — копии плана; «пятница ночь (план)» при тексте «суббота 2:10». А после исправления нашлась обратная дыра: писатель главы N вообще не видел фактов своего плана (#159).
5. **Пересчёт главы снова открывал обещания, закрытые поздними главами.** В «Фоне» таких 38 из 148.
6. **Устаревшая вкладка писала в другую книгу** — в FE и в планировщике. Распознать такую запись после факта невозможно.
7. **Форма State и автосохранение карточки перетирали правки** из другой вкладки и вписанное главой; ключ сессий планировщика менялся при каждом запуске, и правки пропадали молча.
8. **«Готово» после «Принять» приходило раньше анализа, L3 и заметки.** Автор шёл дальше, а следующая глава могла остаться без них.
9. **Новые персонажи вставлялись в начало State.** У «Фона» главная героиня начиналась с 11 650-го знака, и «Подготовить промт», заметка и ИИ-помощь планировщика её не видели.
10. **Тесты, которые ничего не проверяли.** 6 из 88 проверок маршрутов FE падали незаметно; тесты планировщика ходили в настоящий FE с настоящим токеном; дымовая книга сравнивала выбор приложения с ним же.

## Чего не делали и что решил автор

Решения автора по находкам, которые меняли поведение заметно:

- Запасной набор ролей без подписок оставить; судья другой семьи — по ключу, если есть.
- «ГРУБО» критика редактору — только подтверждённое судьёй.
- Авто-оценка нужна — сделана оценкой судьи принятого круга, отдельный оценщик — только для глав без судьи.
- Модели nano в старых инструментах (bench, craft_check) оставить.
- Gemini третьей семьёй не подключать. Замер Argon критиком: цензуры нет (6 жёстких глав, 0 отказов), но судья с его разбором хуже отличает испорченные главы: разрыв 1,6 балла против 6,2 у Haiku, ложное «ГРУБО» у 4 из 8 живых глав.
- Записи OpenAI в hosts и папку .ab_work не трогать.

Не делали сознательно — вреда нет или лечение дороже болезни:

- Мёртвые маршруты FE (на них завязаны тесты-доказательства принадлежности) и мёртвые таблицы старых миграций планировщика (в одной — 5 строк данных).
- Исследовательские скрипты без явной кодировки: их запускают с PYTHONUTF8=1.
- События библии называются по номеру сцены в главе, а не по карточке: переименование сменило бы ключи всех существующих записей.
- Сохранение плана главы в FE не одной транзакцией: повторная отправка безопасна, она заменяет план целиком.

Впереди:

- [ ] Замер правила «кто что знает» на исправленном коде (гл.4 «Ночной смены», по 3 прогона с правилом и без)
- [ ] Пункты 5–6: шум и предвзятость судей
- [ ] Данные «Фона», посчитанные старым кодом (обещания, State ранних глав): «Пересчитать по тексту» по главам, если к книге вернёмся

## Мои промахи по ходу

Ни один не попал в master и не испортил данные книг; все пойманы проверками или CI.

| Промах | Чем обернулся | Как не повторять |
| --- | --- | --- |
| Скрипты правки через bash-heredoc с обратным слешем | Оборванные строки в коде, испорченный путь в README и в скрипте замера | Строки с обратным слешем — через редактор или скрипт файлом |
| `smoke.py --check` по старым прогонам | Перезаписал smoke_report.txt двух прогонов в .ab_work — живые отчёты потеряны | --check пишет в отдельный smoke_check.txt; проверки — на копии папки |
| Правка планировщика без прогона тестов FE | CI упал на тесте «каждая переменная в README» | Любая правка — оба набора тестов и все проверки CI |
