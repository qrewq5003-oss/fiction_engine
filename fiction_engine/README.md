# Fiction Engine — приложение

Веб-интерфейс и CLI поверх движка генерации. Общее описание проекта и
установка — в [корневом README](../README.md).

---

## Интерфейсы

**Браузер** (`http://127.0.0.1:5000`) — основная работа: State Engine,
генерация, pipeline, разбор глав.

**Терминал** (`fiction-engine`, он же `python3 cli.py`) — быстрые действия
без мыши.

| Команда | Что делает |
|---|---|
| `cli.py status` | Статус проекта: главы, состояние, последние оценки |
| `cli.py pipeline` | Полный цикл генерации с критикой и оценкой |
| `cli.py analyze` | Разобрать главу и предложить обновление State Engine |
| `cli.py prompt` | Собрать промпт для ручной генерации |
| `cli.py chapter` | Добавить главу из файла или буфера |
| `cli.py state` | Показать State Engine |
| `cli.py keys` | Ввести и проверить API-ключи |
| `cli.py web` | Открыть веб-интерфейс |
| `cli.py cleanup` | Удалить данные, оставшиеся от удалённых проектов |
| `cli.py version` | Показать версию |

Без аргумента — интерактивное меню.

## Выбор модели

Задача и бюджет, а не «лучшая модель вообще»:

| Задача | Что подходит |
|---|---|
| Генерация прозы | Модель с сильным русским: Claude Opus, GPT-5, специализированные модели прозы через nano-gpt |
| Критика и оценка | Та же или уровнем ниже — задача аналитическая |
| Анализ глав, L3-саммари | Дешёвая и быстрая: работы много, творчества не требуется |

Модель для служебных задач настраивается отдельно в `/settings` — анализ
каждой главы дешёвой моделью заметно снижает расход.

Список моделей — в `engine/api.py`; nano-gpt даёт доступ к 300+ моделям
через один ключ.

## Объём главы и обрыв

Промпты требуют 2500–3000 слов. Для русского это 8–10 тысяч токенов вывода
(≈6.8 символа на слово, ~2–2.5 символа на токен), поэтому потолок
`PROSE_MAX_TOKENS` выставлен с запасом в `pipeline_config.py`.

Если модель всё же упёрлась в потолок, интерфейс показывает баннер
«Продолжить главу»: последние 400 слов сохраняются как режиссёрская
заметка, и следующий запуск дописывает главу с места обрыва. Автоматически
это не запускается — повторный вызов модели стоит денег.

## Разработка

```bash
.venv/bin/python -m pytest tests/ -q --cov=engine --cov=web
.venv/bin/python -m mypy engine web cli.py
python3 check_architecture.py
```

`check_architecture.py` следит за границей слоёв: web-слой не должен
импортировать приватные функции движка. Публичный API — в `engine/__init__.py`
и в докстрингах `pipeline.py`.

Набор один. Раньше их было три — run_tests.py, `tests/` и четыре
неподключённых `tests_*.py` в корне, — одни и те же проверки в двух-трёх
реализациях. При слиянии уникальные случаи перенесены в `tests/`, покрытие
выросло с 71.4% до 77.8%. CI роняет сборку, если покрытие упадёт ниже 75%.
