# Идея
Визуальный планировщик истории в сценарном стиле. Думаешь сценами, видишь акты,
связываешь сцены в граф причинности, смотришь статистику, экспортируешь в Fiction Engine.
Свободный формат — не Final Draft, а инструмент мышления. Один пользователь, локально,
доступ с телефона через Tailscale.

# Архитектура

## Сущности
- `Project` — проект (название, жанр, описание, обложка)
- `Act` — акт (номер, название, цвет). По умолчанию 3: Завязка / Конфронтация / Развязка
- `Scene` — карточка сцены (акт, порядок, локация, время суток, персонажи, что происходит, эмоция, заметки)
- `SceneLink` — связь между сценами (from_id, to_id, тип: cause/parallel/mirror/contrast)
- `SceneSnapshot` — снапшот карточки при изменении (хранится последние 10 на сцену)

## Экраны
- `/board` — основной, колонки по актам, карточки drag & drop; «📥 Импорт главы» — написанная
  глава (из FE или вставленная) разбивается моделью на сцены и связи, автор правит и ставит на доску
- `/map` — граф сцен (Vis.js), узлы = карточки, рёбра = SceneLink; раскладка «по главам» — колонка на главу
- `/scene/<id>` — детальная карточка + AI-ассистент сбоку + история снапшотов
- `/stats` — статистика: по актам, персонажам, локациям, эмоциям, незаполненным полям
- `/export` — выбрал сцены → промт → отправить в Fiction Engine (localhost:5000)
- `/bible` — библия серии связанного проекта Fiction Engine: места, вещи, время событий с
  историей; правка автора — новая запись, прошлое не стирается

## Стек
- Flask на порту 5001
- SQLite (planner.db)
- Vis.js для графа
- Tailscale для доступа с телефона

# Открытые вопросы
- ~~Интеграция с Fiction Engine: читать список проектов FE или независимо?~~
  Решено 2026-09-11: только по HTTP. Планировщик не знает ни пути к базе
  Fiction Engine, ни её схемы, ни API-ключей — он просит FE сделать вызов
  модели (`/api/inline_call`) и забирает контекст проекта
  (`/api/project/context?pid=N`). Адрес настраивается через `FE_URL`.
- Пакеты обоих проектов называются `engine` и `web`. Пока это не мешает
  (планировщик запускается своим процессом), но установить оба пакета в
  одно окружение нельзя — имена столкнутся. Если планировщик тоже станет
  устанавливаемым, имена придётся развести.
