# История изменений

Формат опирается на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — по [семантическому версионированию](https://semver.org/lang/ru/).

Проект дошёл до `0.3.0` без явного версионирования: первый коммит содержал
уже сложившуюся систему, а изменения фиксировались только в
`UNIFIED_ENGINE_MASTER/_archive/IMPROVEMENTS_CRITIQUE.md`. Отсчёт ведётся с `0.4.0` —
первой версии, у которой есть проверяемое основание: зелёные тесты, типы,
CI и документация, сверяемая с кодом автоматически.

### Изменено

- **Sonnet, Haiku и Opus 5.5 по ключу API (24.10).** В списке «Anthropic (прямой)» были только модели 4-го поколения — Claude 5.5 за кредиты API нельзя было выбрать ни в «Мастерской», ни в настройках.
- **Claude по ключу API снова работает (23.10).** Sonnet 5.5 отвергал `thinking: disabled` ошибкой 400 и просил `between_tools` — судья, критик и сверка с планом по ключу падали; способ выключить размышление теперь узнаётся по первому отказу и запоминается для модели. Haiku 5.5 размышлял по умолчанию (его не было в списке думающих) и отдавал весь бюджет ответа размышлению — критик возвращал пустоту; теперь размышление выключено и у него. Подписки Claude это не касается.
- **Оценки кругов сравнимы, лучший круг — не по шуму судьи (замер 23.10, решение автора).**
  - **Судья круга 2 и дальше не получает текст прошлого круга.** С ним Sol ставил тому же тексту в среднем на 0.7 балла больше (6 глав «Ночной смены»: 32.4 против 31.7), а круг 1 оценивался без него — «лучший круг» сравнивал оценки, данные в разных условиях.
  - **Ранний круг выше позднего меньше чем на 2 балла — принимается поздний.** Один и тот же текст Sol оценивает с разбросом до 3 баллов; в замере круг 2 получил 30 в прогоне и 32, 33, 32, 32 повторно, а «Принять» взял круг 1 с 33 и выбросил правку. Окно «Принять» объясняет такой выбор.
  - Фильтр правок той же проверкой не задет: на 38 фрагментах в обоих порядках Sol выбирал первый вариант в 50 % ответов.
- **Планировщик: безопасность, тесты, мелочи (разбор планировщика 21.10, пакет C).**
  - **Открытый редирект после входа** (FE и планировщик): адрес вида «/<табуляция>/evil.example» проходил проверку, и браузер уходил на чужой сайт. Управляющие символы и обратный слеш теперь снимаются до проверки.
  - **Тесты планировщика**: доказательство принадлежности для «Новый проект» слало форму и получало 415 — не проверяло ничего; ветка экспорта «FE недоступен» не проверялась ни разу (тест брал несвязанный проект); проверки снимков «≥ 1» и «≤ 10» проходили и при нуле; тест подсказок моделей проверял то, чего в странице давно нет; дубль теста статуса; тесты не читают `.env` разработчика (`PLANNER_NO_DOTENV`).
  - **Мелкое**: проверка времени не считает 31 декабря → 1 января «датой раньше»; адрес FE без `FE_URL` берёт `FE_PORT`; `python-dotenv` в зависимостях планировщика (без него `.env` FE тихо не читался); «Скопировать план» по сети без https говорит, что не вышло; разбивка главы предупреждает, что конец длинной главы в неё не вошёл; числа из FE на страницах — только числами.
- **Планировщик ↔ FE (разбор планировщика 21.10, пакет B).**
  - **Факты плана главы N видны писателю и анализу главы N.** Срез библии «до главы N» выбрасывал записи с номером самой главы — а план пишется именно под ним; правка автора «с главы N» тоже не действовала в главе N. Из-за этого не срабатывало и правило «текст важнее плана».
  - **Номер главы в экспорте**: FE не ответил — поле пустое с предупреждением (было молча 1, и «Отправить» перезаписывал план главы 1); номер берётся лёгким списком глав.
  - **Доска говорит «план в FE устарел»** для глав, чьи сцены поправили, переставили или удалили после отправки; повторная отправка снимает отметку.
  - **Экспорт**: ждёт FE до 60 с (было 10 при ожидании базы FE до 15); тайм-аут — «неизвестно, дошёл ли — отправь ещё раз», а не «FE недоступен»; предупреждает, что сцена была в плане другой главы и что факты библии берутся из карточек, если план правлен в окне.
  - **План вперёд для сторожа забеганий** — с нынешними планами следующих глав из FE, а не снимком доски на момент экспорта.
  - **ИИ-помощь**: книга на момент главы сцены (не на конец книги), State героев сцены по её тексту (было — первые знаки State, у «Фона» без главной героини), сцена — только своего проекта.
  - **Честные ошибки**: «FE ответил 401 — не подошёл токен» вместо «FE сервер выкл.»; статус видит подписки (было «Нет API ключей» при работе только по ним); разбивка главы и ИИ-помощь ждут дольше предела FE для подписки.
- **Планировщик: данные и вкладки (разбор планировщика 21.10, пакет A).**
  - **Устаревшая вкладка не пишет в другой проект**: страницы шлют свой проект (`X-Planner-Project`), сервер отвечает 409, если в другой вкладке открыт другой.
  - **Карточка сцены** при сохранении и автосохранении шлёт только изменённые поля и версию: правки из другой вкладки, «Восстановить» и перенос на доске больше не затираются молча; при конфликте — вопрос, а правки при уходе сохраняются черновиком в браузере и предлагаются при следующем открытии. Двойной клик «Сохранить» на новой карточке не создаёт две сцены.
  - **Ключ сессий постоянный** (`SECRET_KEY`, `FLASK_SECRET_KEY` или файл `~/fiction_engine/planner_secret.key`): был новым при каждом запуске — после перезапуска открытые карточки получали отказ, автосохранение теряло правки.
  - **Удалённые сцены — в корзину доски** (кнопка «🗑 Корзина», вернуть со связями): снимок «удалена» стирался вместе со сценой.
  - **Перетаскивание** ставит сцену туда, куда её бросили, и перенумеровывает оба акта (были дубли позиций и неопределённый порядок, а от него — план главы); перенос больше не пишет «версию» и не вытесняет настоящие версии текста. Порядок сцен — по номеру акта, у сцен без акта — разные позиции.
  - **«Восстановить» версию** берёт только текст — не двигает сцену на старое место и не падает, если акт удалён. Сохранение сцены не принимает акт чужого проекта.
  - **«Акты → Сохранить»** — все акты одним запросом: обмен номерами и новый акт после удаления больше не теряются молча; ошибки показываются.
  - **Граф**: повторная связь обновляет ребро, а не рисует дубль; удаление связи — только при согласии сервера.
  - **Повторный импорт главы** может заменить прежние сцены главы (они уходят в корзину): иначе экспорт уносил в план оба комплекта.
  - **Мелкое**: сбой на запросе страницы — JSON с причиной, а не «Unexpected token <»; нечисловые номера — 404, а не 500; перепривязка проекта к другой книге FE — с вопросом; удаление другого проекта не сбрасывает открытый.
  - **Тесты планировщика** не ходят в настоящий FE и не пишут ключ в домашнюю папку.
- **Судейская часть по решениям автора (21.10).**
  - **Авто-оценка главы** — оценка судьи принятого круга, без нового вызова модели (был отдельный оценщик на каждую главу: лишний вызов подписки и вторая оценка со своим шумом). Отдельный оценщик — только для глав без судьи (загруженных, правленых вручную) и по правилам v2: без строки вне балла или с «ГРУБО» — не «ПРИНЯТЬ».
  - **График качества на «Статистике»** рисовал итог из 50 по шкале 10 и ждал критерии прежнего формата — теперь шкала 50, пять нынешних критериев, источник оценки.
  - **Редактору первым — «ГРУБО», подтверждённое судьёй.** Если судья снизил «ГРУБО» критика до «ЕСТЬ», пункт остаётся обычным замечанием.
  - **Запуск помнит правила оценки** (v1/v2), с которыми начат: «Ещё круг» после переключения судил бы по новым, и «лучший круг» сравнивал бы баллы разных шкал.
  - **Сбой критика или судьи** — круг без разбора или без оценки и предупреждение, а не ошибка 500 с потерей главы на экране; лучший круг выбирается среди оценённых.
  - **Запасной набор ролей** (без подписок) оставлен; если к судье другой семьи есть ключ, судьёй ставится он — иначе запуск скажет, что судьи другой семьи нет.

- **Планировщик: «📥 Импорт главы» на доске.**
  - Написанная глава связанного проекта FE (или вставленный текст) разбивается моделью на сцены: название, место, день, время суток, персонажи, что происходит, эмоция. Модель также предлагает связи для графа, в том числе со сценами прошлых глав на доске.
  - Сначала окно предпросмотра: поля можно поправить, лишнее снять галочкой. Связи соседних сцен по умолчанию сняты: модели проводят цепочку 1→2→3, которая только повторяет порядок доски.
  - Сцены встают в акт по порядку глав (глава 2 между 1 и 3, в каком бы порядке ни импортировали), с меткой «гл.N».
  - Граф: раскладка «по главам» — колонка на главу; на рёбрах значок типа, пояснение связи при наведении.
  - FE: `/api/chapters/list?pid=`, `/api/chapter/<n>/text` принимает `?pid=`. Контрактный тест теперь видит и GET-запросы планировщика (`_fe_get`).
  - По умолчанию главу разбивает модель, которая её писала (генерация принятого запуска; FE отдаёт её в списке глав). На копии книги автора, главы 1–3: Sonnet (писал книгу) — 6 сцен в главе и 8 связей с прошлыми главами; DeepSeek V4 Pro — 9–11 сцен и одна такая связь.

  - На телефоне: меню по ☰, колонки в одну, AI-помощь в сцене видна, правка и удаление карточек без наведения.
- **Отрывки прошлых глав писателю** (`engine/excerpts.py`, шаг 3

### Добавлено

- **Ручная правка и удаление глав.** Текст главы в конвейере правится прямо в
  окне результата — «Принять» сохраняет его с правками. На странице главы —
  «✏️ Редактировать / 💾 Сохранить» (`POST /chapter/<n>/save`). Удалить главу
  раньше было нельзя ни из одного места: теперь 🗑 в списке глав на «Обзоре» и на
  странице главы (`POST /chapter/<n>/delete`, `db_chapters.delete_chapter`).
  Вместе с главой удаляются её L3-саммари, анализ, оценки, замер голоса и
  непримененные обновления State; State не откатывается, история запусков и
  правки автора остаются.
- **«📂 Открыть» в истории запусков.** Прогон возвращается на страницу с текстом,
  оценками и кнопками «Принять / Отклонить». Раньше результат жил только в
  памяти страницы: ушёл на «Обзор» — дописанную главу было не вернуть, хотя она
  целиком лежит в базе.
- **«🧹 Очистить» на странице нарративного анализа.** Убирает показанный отчёт и
  анализ глав, которых в проекте больше нет (`/narrative/purge`,
  `db_chapters.purge_orphan_chapter_data`): анализ удалённых и непринятых глав
  считался в отчёте как настоящий.
- **Карточка главы: проверка непрерывности и правка.** На страницах генерации и
  конвейера — отдельный блок: проверено ли, сколько замен, сколько кругов, кто
  проверял и правил; раскрывается список «было → стало» по каждому противоречию
  и то, что осталось, с цитатами. Раньше итог шёл одной строкой предупреждения
  (в конвейере — всплывающим сигналом на 12 секунд). Поле `continuity` в ответе
  генерации; `cross_check_and_fix(…, report=)`.
- **Сигнал о смене формата диалога по серии.** Реплики в главе оформлены не так,
  как в прошлых главах серии (тире с абзаца или кавычки) — подсказка автору. На
  готовых сериях DeepSeek меняет формат в 16 сериях из 36, Sonnet — ни разу.
  `text_signals.dialogue_format`, замер — `tools/voice_drift.py`.
- **Правка по находкам проверки непрерывности — по выбору автора.** «Настройки →
  Проверка непрерывности → Правка по находкам»: выбранная модель исправляет
  найденные противоречия на месте — заменяет только фрагменты с неверным фактом,
  потом проверка повторяется, автору остаётся то, что не снялось. Обе дороги
  генерации; в конвейере правленая глава — отдельная итерация `continuity_fix`.
  На замере правщик Sonnet 5.5: противоречий 104 → 10, судья за правленую главу
  11 : 5; DeepSeek в роли правщика ломает связность (12 : 5 за исходник).
  `engine/continuity_fix.py`, пилот — `tools/fix_pilot.py`.
- **Правка по находкам — до двух кругов.** Если после правки перепроверка
  находит ещё противоречия, правка повторяется один раз. На замере второй круг:
  49 → 2, проза по судье не хуже (8 : 7).
- **Время в плане — без модели.** Планировщик читает поле «время» сцен
  (день недели, дата, часы, часть суток, «на следующий день», «через»,
  флешбэк) и в порядке доски подсказывает: день недели скачет на 4–6 дней
  (четверг → вторник), «на следующий день» не тот день, дата раньше прежней,
  даты и дни недели не сходятся, в тот же день время назад. Подсказки — на
  странице статистики и при составлении плана главы перед экспортом.
- **Вход по паролю в планировщик.** `PLANNER_PASSWORD`, а без него —
  `FE_PASSWORD`: одного пароля хватает обоим приложениям. С паролем без
  входа не открывается ни одна страница; не на петле без пароля планировщик
  не запускается (раньше только предупреждал). Запросы, меняющие данные,
  несут токен CSRF, как в Fiction Engine.
- **Проверка непрерывности после главы — по выбору автора.** «Настройки →
  Проверка непрерывности»: выбранная модель сверяет новую главу с полным
  текстом трёх прошлых и даёт до 8 сигналов «Противоречие с главой N»
  парой цитат (цитаты проверяются по тексту). Не выбрана — вызова нет.
  Проверяющий того же семейства, что писатель, — с предупреждением. На
  замере GPT-6.1 Sol: 84 % находок настоящие (Sonnet 70 %, DeepSeek 30 %).
  Обе дороги генерации: `run_generation` и конвейер.
- **GPT через подписку ChatGPT — личный провайдер, выключен по
  умолчанию.** При `FE_CHATGPT_SUBSCRIPTION=1` модели GPT вызываются через
  `codex exec` (вход `codex login`): пустая папка, песочница read-only,
  инструменты выключены, глубина размышления — в имени после `@`.
  `engine.api.chatgpt_limits()` — остаток лимитов 5 часов и недели. GPT —
  семейство, отдельное от Claude, поэтому годится проверяющим и судьёй для
  глав Claude. Тесты: `test_chatgpt_subscription.py`.
- **Замер GPT-6.1 Sol как писателя** (`bench/ab-writers-gpt61-2026-10-15.json`):
  против DeepSeek все устойчивые голоса трёх судей за GPT (11 из 11), против
  Sonnet устойчивых голосов два, оба за Sonnet. Главы короче (2500–2900
  слов). В списке моделей GPT-6.1 Sol отмечен ★.
- **Планировщик и библия серии.** Импорт проекта Fiction Engine запоминает
  связь; план главы уходит в этот проект (а не в открытый в FE) вместе с
  фактами сцен — место, время, кто — и они попадают в библию до того, как
  глава написана. Страница «Библия» в планировщике показывает места, вещи и
  время событий с историей и противоречиями; правка автора — новая запись.
- **Библия серии.** Анализ главы ведёт карточки мест, вещей и событий с
  атрибутами (этаж, адрес, чья вещь, где лежит, день, время). Записи только
  дописываются: изменение по сюжету — с причиной, уточнение — отдельно,
  смена без события — противоречие, видное автору, а прежний факт остаётся.
  Генератор получает их блоком «пиши ровно так». На замере противоречий на
  серию на 25–30 % меньше у трёх наборов судей из четырёх.
- **Предупреждение о пристрастном судье.** Если в пайплайне главу пишет
  Claude и судит тоже Claude — или судит та же модель, что писала, — автор
  видит предупреждение: на замере Claude узнавал текст Claude 16 раз из 16
  и голосовал за него, оценка такого судьи завышена.
- **Проверка второй линии книги.** У проекта со вторым жанром из семейств
  романтика, триллер, хоррор после вердикта судьи — пять вопросов о ремесле
  этой линии (показано или названо, напряжение, подготовка, живость, подтекст
  — свои для каждого семейства). Сумма ≤ 5.5 из 10 — замечание в вердикте и
  «НА ДОРАБОТКУ». Нет линии в главе — проверка молчит. Остальные семейства не
  включены: на замере открытые модели там провал не видят.
- **Безопасность (ROADMAP, этап 5.1–5.3).** Вход по паролю `FE_PASSWORD`;
  на не-петлевом адресе без пароля Fiction Engine не запускается. Ключи
  провайдеров в базе зашифрованы (Fernet), ключ шифрования — в
  `~/fiction_engine/secret.key` с правами 600 или в `FE_SECRET_KEY`; ключи,
  сохранённые раньше, шифруются при первом запуске. Запрос, меняющий данные,
  без токена CSRF отклоняется; страницы добавляют токен сами, планировщик
  ходит с заголовком `X-FE-Token`. Новая зависимость — `cryptography`.
- **Claude через подписку Claude Code — личный провайдер, выключен по
  умолчанию.** При `FE_CLAUDE_SUBSCRIPTION=1` модели Claude Sonnet / Opus /
  Haiku вызываются через залогиненный `claude` CLI и списываются с подписки
  Pro/Max. Риски для аккаунта и ограничения — в README («Claude через
  подписку — только для себя»). Вызовы строго по одному.

### Изменено

- **Отчества персонажей держатся всю серию.** Первые отчества из уже
  написанных глав идут генератору и проверке continuity, а если отчество у
  того же имени всё же сменилось — автор получает сигнал. По тексту, без
  модели. На замере смен отчества 0 в 4 сериях против 10 без реестра.
- **Детали серии в State.** Анализ главы выписывает вещи и их приметы,
  приметы мест, время событий, числа (номера, адреса, суммы); они копятся
  в plot_matrix разделом «ДЕТАЛИ СЕРИИ» и передаются генератору и проверке
  continuity. На замере противоречий меньше (2.64 против 3.57 на серию),
  но разница в пределах шума.
- **`series-continuity` не считает молчание судьи нулём.** Неразборчивый
  ответ отбрасывается, ответ списком принимается; сторона подписывается по
  `label` набора.
- **Сигналы о повторах между главами серии.** К проверке готовой главы
  добавлено сравнение с четырьмя предыдущими главами проекта: оборот в трёх
  главах подряд, глава начинается или кончается так же, как предыдущая,
  дословный кусок из прошлой главы (пересказ). Считается по тексту, при
  любом генераторе; на 32 главах серий замера — 9 сигналов, все по делу.
- **Сигналы автору по готовой главе — при любом генераторе.** Новый модуль
  `engine/text_signals.py` проверяет сам текст: частые сравнения «словно /
  будто», обороты «не X, а Y», цепочки «…, и …, и …», штампы эмоций, повтор
  слова, многоточия, однообразные начала фраз. Пороги — по 9 главам из 10 в
  наборах трёх генераторов (GLM, Kimi, DeepSeek), поэтому сигнал получает
  выделяющаяся глава, а не привычки одной модели. Текст не правится.
- **Свой пресет голоса для психологического триллера.** Пресет триллера
  написан под триллер действия и психотриллеру вредил (−0.45, затем −0.20).
  Новый — сомнение героя в своём восприятии, двусмысленность близких, угроза
  в обыденном; замер: −0.02 ± 0.16, вред ушёл.
- **Разделы поджанров ищутся по ключу жанра, а не по русской метке.** В
  контрактах и жанровых промптах базы — якоря `<!-- genre: ключ -->`;
  таблицы меток удалены. Текст для модели не изменился ни в одном жанре.
  Раньше раздел искался подстрокой метки, и расхождение формы («ИСТОРИЧЕСКИЙ»
  против «ИСТОРИЧЕСКАЯ РОМАНТИКА») молча давало чужой контракт.
- **Шесть стилей серии переписаны: конкретные приёмы вместо общих формул.**
  Подсчёт по текстам показал, что атмосферный, эпический, эмоциональная
  глубина, всезнающий, коммерческий и кинематографичный стили почти не

## [0.4.1] — 2026-09-15

Версия про то, как движок себя проверяет. Внешних возможностей не
добавилось.

Измерения, на которых стоят все пункты ниже, приведены в
[ROADMAP_TEXT.md](ROADMAP_TEXT.md) — здесь только то, что изменилось.
Числа не дублируются намеренно: копии расходятся, и за эти три дня в коде
нашлось четыре таких расхождения.

### Исправлено

Девять мест, где проверка молча возвращала правдоподобную ложь:

- **Критику подсказывали ответ** — программный замер ритма клался в его
  промпт перед текстом главы, и критик исправно называл ритм главной
  проблемой.
- **Критик видел треть главы** и судил по ней о финале; **проверка
  непрерывности** — четверть; **поиск символов** — четверть; **оценка
  стиля** — пятую часть. Комментарии утверждали, что этого достаточно; ни
  одно утверждение не было проверено.
- **Пустой ответ модели принимался за текст** — оценка 0 из 50,
  неотличимая от «модель написала плохо».
- **Обрыв главы на полуслове не ловил никто:** провайдер сообщает чистый
  `stop`, объём в норме, а судья к обрыву слеп.
- **Главная претензия критика терялась** в одной главе из шести, когда он
  перечислял нарушения не под своим заголовком.
- **Форма ответа поиска символов не гарантирована** — голый список вместо
  объекта давал пользователю 500.

### Изменено

- **Порог принятия главы: `≥ 30` и каждый критерий `≥ 4`** вместо `≥ 40`
  и `≥ 7`. Прежний не брала ни одна глава ни разу, то есть вердикт «НА
  ДОРАБОТКУ» не означал ничего. Новые числа выбраны по разделяющей
  способности на нарочно испорченных текстах, а не по медиане.
- **Числа, названные в промптах, сведены к константам:** норма ритма,
  требование к объёму, порог вердикта. Промпты подставляют, а не
  повторяют.
- **Правило о деталях** вместо «Место: с одной атмосферной деталью» —
  промпт заказывал украшение, за которое критик снижает оценку. Сдвига
  оценки от этой правки не измерено.

### Добавлено

- **`tools/bench.py`** — повторяемый замер качества: фиксированный посев
  во временной БД, хэши промптов генерации и критика, предупреждение при
  сравнении замеров разными версиями измерителя.
- **Разброс замера измерен** и оказался велик: по одному прогону различим
  только сдвиг примерно от восьми баллов из пятидесяти. Поэтому оценки
  убраны из списка моделей — прежний рейтинг был шумом.
- **Редактура на первой итерации** (`PIPELINE_GENERATE_AND_EDIT`).
  Набором по умолчанию не становится: парный замер отдачи не показал.

## [0.4.0] — 2026-09-11

Версия ревизии. Внешних возможностей не добавилось; починено то, что
годами не работало, и выстроен контур, который не даст этому повториться.

### Исправлено

- **База знаний не попадала в промпты.** В `engine_loaders` у `load_module`
  единственного из всех загрузчиков не было обёртки, подставляющей путь
  движка: имя модуля уходило в параметр `engine_path`, дальше `str / str` →
  `TypeError` → перехват как `RECOVERABLE` → пустой блок. В логе
  пользователя 70 таких срабатываний. Контекст движка: `quick` 0 → 16 343,
  `quality` 0 → 37 057, `master` 0 → 48 633 символа.
- **Автообновление State Engine уничтожало анализ.** Читались колонки
  `new_global_state` и `new_plot_matrix`, которых в таблице нет: оба `.get()`
  давали `None`, состояние переписывалось само в себя, задача помечалась
  выполненной, а интерфейс сообщал об успехе. Применение переведено на
  `merge_analysis_into_state` — тот же путь, что у ручной кнопки.
- **Слияние анализа в State не работало ни на одном реальном формате.**
  Парсер искал `СОСТОЯНИЕ:`/`ЛОКАЦИЯ:` в верхнем регистре и
  регистрозависимо, тогда как форматов оказалось три (шаблон кода, шаблон
  базы знаний, авторский), а живые файлы хранятся в CRLF — из-за чего `$`
  в регулярных выражениях не совпадал вообще. Парсер стал терпимым:
  синонимы ключей, заголовки `### Имя` / `[ИМЯ — РОЛЬ]` / `**Имя**`,
  устойчивость к CRLF. Отчёт об изменениях выдаётся только при фактической
  правке текста — ложное «Применено N изменений» устранено.
- **Жанровая линза критика не применялась к русским жанрам:** таблица линз
  на английских ключах получала на вход «городское фэнтези» и молча
  откатывалась на нейтральную.
- **Исключения не доходили до `engine_error_log`:** `DBHandler.emit` звал
  `self.formatException`, которого у `logging.Handler` нет. Запись терялась
  ровно тогда, когда логируется исключение.
- **Страницы отдавали 500 при отсутствии проекта:** 21 ссылка на
  `url_for("main.index")`, тогда как блупринта `main` в проекте нет.
  Плюс незакрытый `{% block %}` ломал `/stats`.
- **Сортировка по `created_at` без вторичного ключа** в 8 местах: метка
  имеет секундную точность, поэтому «последнее обновление» и «свежие
  правки» врали при любой паре записей внутри одной секунды.
- `delete_project` чистил 6 таблиц из 17; `PRAGMA foreign_keys` не
  включался вовсе. Живая база пользователя содержала 11 осиротевших строк.
- `log_error` нарушал обещание «никогда не бросает»: аварийный путь ловил
  только `sqlite3.Error`.
- Потолок вывода стоял ниже требуемого объёма главы (`generate` 8000,
  `edit` 7000 при потребности 8 100–10 200 токенов на 3000 слов), причём
  редактура была теснее генерации. Бюджет выводится из целевого объёма.
- Обрыв ответа по лимиту токенов не распознавался: `stop_reason` и
  `finish_reason` отбрасывались всеми пятью провайдерами.

### Добавлено

- Распознавание обрыва главы и баннер «Продолжить главу» на страницах
  генерации и pipeline — подключён к уже существовавшему сохранению хвоста.
  Автозапуск сознательно не делается: повторный вызов модели стоит денег.
- `PRAGMA foreign_keys`, `journal_mode=WAL`, `busy_timeout` в соединении.
- Команда `fiction-engine cleanup` — удаление данных от удалённых проектов.
- Проект ставится пакетом: `pip install -e .`, команды `fiction-engine`
  и `fiction-engine-web`.
- CI на GitHub Actions: тесты с покрытием, mypy, границы слоёв,
  собственные AST-анализаторы в `tools/`.
- Документация: корневой `README.md`, переписанный `fiction_engine/README.md`,
  `LICENSE`, `PROJECT_REVIEW.md`, `ROADMAP.md` и тест, который роняет
  сборку при расхождении документации со структурой кода.

### Изменено

- Оба сервера по умолчанию слушают `127.0.0.1`, наружу — осознанно через
  `FE_HOST` / `PLANNER_HOST`.
- Ключ подписи сессий больше не берётся из плейсхолдера, лежащего в
  репозитории.
- `setup.sh` создаёт venv вместо установки в систему: на SteamOS и других
  системах с неизменяемым `/usr` прежний путь не работал в принципе.
- Тесты сведены в один набор: удалены `run_tests.py` и четыре
  неподключённых `tests_*.py` в корне, −14 186 строк дублирования.
  Уникальные случаи перенесены, покрытие выросло с 71.4% до 77.8%.
- Тихие перехваты исключений: 40 → 7, оставшиеся живут внутри логгера
  и задокументированы.
- `generate_bp.py` (905 строк) разнесён на четыре модуля, `pipeline.py`
  (858) разделён на оркестратор и два подмодуля — без изменения
  публичных путей импорта.
- Строгая типизация (`disallow_untyped_defs`) на 22 модулях вместо 3.

### Безопасность

- API-ключи по-прежнему хранятся в SQLite открытым текстом, а сетевой
  режим не требует аутентификации — см. этап 5 в [ROADMAP.md](ROADMAP.md).
- Рабочая БД планировщика и артефакты сборки убраны из индекса git.
  В истории первого коммита они остались.
