# Fiction Engine

Инструментарий для написания длинных серий прозы с помощью языковых моделей.
Держит состояние мира между главами, собирает промпты из базы писательских
приёмов и прогоняет текст через цикл «генератор → критик → редактор → судья».

Локальный, однопользовательский, данные не покидают машину (кроме запросов
к выбранному API модели).

---

## Три части

| Часть | Что это | Запуск |
|---|---|---|
| **`fiction_engine/`** | Приложение: веб-интерфейс, CLI, движок генерации и State Engine | `:5000` |
| **`UNIFIED_ENGINE_MASTER/`** | База знаний: 233 файла приёмов, жанровых каталогов, чек-листов и шаблонов промптов | подключается движком |
| **`planner/`** | Визуальный планировщик сцен: доска, граф причинности, экспорт в Fiction Engine | `:5001` |

`UNIFIED_ENGINE_MASTER` — не документация, а рабочие данные: движок читает
оттуда модули и вставляет их выжимки в системный промпт генерации.

---

## Установка

Нужен Python 3.10+.

```bash
bash fiction_engine/setup.sh
```

Скрипт создаёт `.venv`, ставит зависимости, генерирует `.env` со случайным
`FLASK_SECRET_KEY` и инициализирует базу.

На системах с неизменяемым `/usr` (SteamOS, Fedora Silverblue) это
единственный рабочий путь: системный `pip` там недоступен.

Вручную:

```bash
cd fiction_engine
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -c "import sys;sys.path.insert(0,'.');from engine.db import init_db;init_db()"
```

## Запуск

```bash
bash start_all.sh          # оба приложения сразу
```

По отдельности:

```bash
cd fiction_engine && .venv/bin/python web/app.py     # http://127.0.0.1:5000
cd fiction_engine && .venv/bin/python cli.py         # терминальный интерфейс
cd planner        && python3 app.py                  # http://127.0.0.1:5001
```

Оба сервера по умолчанию слушают только петлевой интерфейс: аутентификации
нет, а в базе лежат API-ключи. Чтобы открыть доступ с телефона (например
через Tailscale) — осознанно:

```bash
FE_HOST=0.0.0.0 .venv/bin/python web/app.py
```

## Первые шаги

1. **Ключи** — `/settings` в браузере или `python3 cli.py keys`.
   Поддерживаются Anthropic, OpenAI, Google Gemini, DeepSeek напрямую
   и nano-gpt.com как шлюз к 300+ моделям.
2. **Проект** — название и жанр серии. Жанр определяет, какие модули базы
   знаний подключатся и какой линзой будет смотреть критик.
3. **State Engine** — `/state`: персонажи, сюжетные линии, кто что знает.
   Это то, что движок подставляет в промпт каждой следующей главы.
4. **Главы** — загрузить уже написанные (`.txt`/`.docx`) или генерировать.

## Как это работает

```
         ┌──────────────────── UNIFIED_ENGINE_MASTER ───────────────────┐
         │  приёмы · жанровые каталоги · чек-листы · шаблоны промптов   │
         └──────────────────────────────┬───────────────────────────────┘
                                        │ выжимки модулей по жанру и режиму
                                        ▼
  State Engine ──┐            ┌──────────────────┐
  L3-саммари ────┼──────────► │  сборка контекста│ ──► промпт
  голос автора ──┤            └──────────────────┘
  подготовка ────┘                     │
                                        ▼
              ┌─────────────────────────────────────────────┐
              │  генератор → критик → редактор → судья      │  pipeline
              │            ▲                    │           │
              │            └──── авто-повтор ◄──┘           │
              └─────────────────────┬───────────────────────┘
                                    ▼
                    глава ──► анализ ──► обновление State Engine
```

Каждая написанная глава анализируется и возвращается в State Engine, чтобы
следующая генерация знала, что изменилось в мире.

**Режимы**: `QUICK` — черновик, `QUALITY` — с критикой и судьёй,
`MASTER` — с редактурой и авто-повтором при низкой оценке.

## Где лежат данные

```
~/fiction_engine/
├── projects.db      все проекты, главы, State Engine, ключи, история
├── engine.log       структурированный лог (5 МБ, 3 ротации)
├── prompts_out/     сохранённые промпты
└── prompts_debug/   дампы собранных контекстов
```

Резервная копия — это копия `projects.db`. Команда
`python3 cli.py cleanup` удаляет данные, оставшиеся от удалённых проектов.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `FLASK_SECRET_KEY` | Подпись сессий Fiction Engine | случайный при старте (сессии сбрасываются) |
| `FE_HOST` / `FE_PORT` | Адрес веб-интерфейса | `127.0.0.1` / `5000` |
| `SECRET_KEY` | Подпись сессий планировщика | случайный при старте |
| `PLANNER_HOST` / `PLANNER_PORT` | Адрес планировщика | `127.0.0.1` / `5001` |
| `PLANNER_DB` | Путь к базе планировщика | `planner/planner.db` |
| `FICTION_DEBUG` | Подробный лог в консоль | выключено |
| `ANTHROPIC_API_KEY` и прочие `*_API_KEY` | Ключи, если не хранить в базе | — |

Ключи можно держать в `.env` (файл в `.gitignore`) либо ввести в `/settings`.

## Разработка

```bash
cd fiction_engine
.venv/bin/python -m pytest tests/ -q     # основной набор
.venv/bin/python run_tests.py            # автономный набор, без внешних зависимостей
.venv/bin/python -m mypy engine web cli.py
python3 check_architecture.py            # границы слоёв: web не лезет в приватное
```

Собственные анализаторы в `tools/` (запускать из корня репозитория):

```bash
python3 tools/sigcheck.py fiction_engine                      # сигнатуры вызовов
python3 tools/pitfalls.py fiction_engine --skip-tests --fail-on-new
python3 tools/dead.py    fiction_engine                       # недостижимый код
```

Всё это гоняется в CI на каждый push. Состояние проекта и план развития:
[PROJECT_REVIEW.md](PROJECT_REVIEW.md) и [ROADMAP.md](ROADMAP.md).
